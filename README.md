# NUMMAZA

Бюджет-ассистент для Казахстана. Главная цифра — «Сегодня можно потратить». Приложение разбирает PDF-выписку Kaspi Gold (а также Halyk, Freedom и CSV), раскладывает траты по конвертам, следит за целями и отвечает на вопросы через ассистента Numa — на русском, казахском и английском.

Два режима работы:

- **С сервером** (`server/`): регистрация и вход через сервер, данные синхронизируются между телефоном и компьютером. Выписка всё равно разбирается на устройстве — на сервер уходят уже готовые операции.
- **Без сервера**: если адрес сервера не задан, аккаунт и данные хранятся только на устройстве. Так работает демо-версия на claude.ai.

|---|---|

| `app/js/parser.js` | Разбор PDF/CSV-выписок, распознавание магазинов и своих переводов |
| `app/js/numa.js` | Ассистент Numa: понимает вопрос (RU/ҚАЗ/EN) и считает ответ по данным |

| `app/js/app.js` | Экраны, навигация, действия, отмена через тост |
| `app/js/config.js` | Адрес сервера (пусто — режим без сервера) |
| `app/js/api.js` | Запросы к серверу: регистрация, вход, токены |
| `app/js/sync.js` | Синхронизация данных между устройствами |

## Функции

- Регистрация и вход через сервер: пароль хранится как scrypt с солью, 5 ошибок → блокировка на 15 минут, токены доступа на 15 минут и обновления на 30 дней (с ротацией), удаление аккаунта стирает все данные на сервере.
- Синхронизация: изменения уходят на сервер через 2 секунды, без интернета копятся в очереди и отправляются позже; при конфликте побеждает более позднее изменение. Переписка с Numa не синхронизируется.
- Онбординг в 4 шага: язык и тема, доход и день зарплаты, первая цель, выписка или пример данных.
- «Сегодня можно потратить» с раскрываемой формулой; перерасход распределяется на оставшиеся дни.
- Календарь трат (уровни цвета считаются от дневного лимита), ближайшие обязательные платежи, советы с суммой экономии.
- Траты из уведомлений банка (Android): после разрешения «Доступ к уведомлениям» приложение читает уведомления Kaspi, Halyk и других банков о покупках и переводах и само добавляет операции. Повторы и коды подтверждения пропускаются, уведомления разбираются на телефоне и никуда не отправляются; при загрузке выписки такие операции заменяются строками выписки.
- Анализ периода на «Обзоре»: линия плана (доход минус взносы в цели), накопленные траты, прогноз до зарплаты и категории в сравнении с прошлым периодом за те же дни.
- Импорт выписки: PDF Kaspi/Halyk/Freedom и CSV, пропуск дубликатов, переводы между своими счетами не считаются тратами, сомнительные операции помечаются «проверьте».
- Исправление категории с правилом «всегда так для этого магазина».
- Конверты: лимиты по категориям, автопредложение лимитов, запрет лимитов выше дохода, перенос денег между конвертами.
- Ассистент Numa: бюджет, переплаты, лимит на сегодня, траты по категории, подписки, цели, депозиты (с оговоркой), дорогие дни недели; у каждого ответа есть «на чём основан ответ».
- Цели: статус «опережаете / по плану / отстаёте», отметки 25/50/75%, экран-поздравление на 100%.
- Итоги месяца в формате сторис, «Поделиться» со скрытыми суммами.
- Android: NUMMAZA есть в меню «Поделиться» и «Открыть с помощью» — выписку из Kaspi (PDF/CSV) можно отправить прямо в приложение; если пользователь ещё не вошёл, файл ждёт входа и разбирается сразу после него.
- Добавление операции вручную с цифровой клавиатурой, живой подсказкой по конверту и черновиком на 10 минут.
- Отмена через тост вместо «Вы уверены?», работа без интернета, дневная/ночная тема, три языка, версия для компьютера с боковым меню.
- Экран «Что нового» после обновления (история версий — в `CHANGELOG.md`). Текущая версия — 1.2.

## Запуск

Без сервера: откройте `app/index.html` в браузере.

С сервером на своём компьютере (база в памяти, ничего устанавливать не нужно):

```bash
cd server && npm install && npm run dev
```

Откройте http://localhost:8080. Чтобы данные не пропадали после перезапуска, вместо `npm run dev` запустите `PGLITE_DIR=./data node index.js`.

## Сервер

| Адрес | Что делает |
|---|---|
| `POST /api/auth/register` | Регистрация: имя, телефон (+7) или email, пароль |
| `POST /api/auth/login` | Вход |
| `POST /api/auth/refresh` | Новая пара токенов (старая перестаёт работать) |
| `POST /api/auth/logout` | Выход: сессия отзывается |
| `GET /api/me`, `DELETE /api/me` | Аккаунт; удаление аккаунта и всех данных |
| `POST /api/sync` | Отправить изменения и получить новые с других устройств |
| `GET /api/health` | Проверка, что сервер и база работают |

Переменные окружения: `DATABASE_URL` (PostgreSQL), `PORT`, `ALLOWED_ORIGINS` (другие сайты, которым можно обращаться к API), `ALLOW_FILE_ORIGIN=0` (запретить запросы из Android-приложения).

SMS пока не подключены: `server/sms.js` — заготовка, код пишется в лог сервера. Чтобы включить подтверждение телефона и восстановление пароля, допишите в нём отправку через казахстанский SMS-сервис и передайте ключ через переменную окружения.

## Размещение сервера

### Render (бесплатно, для демонстрации)

1. Загрузите проект в репозиторий GitHub.
2. На render.com: New → Blueprint → выберите репозиторий. Render прочитает `render.yaml` и создаст сервер и базу PostgreSQL.
3. Через несколько минут сервер будет доступен по адресу вида `https://nummaza.onrender.com`. Там же открывается веб-версия.

Бесплатный сервер на Render засыпает без запросов, первый запрос после паузы идёт дольше. Бесплатная база Render удаляется через ограниченный срок — перед защитой проверьте условия на render.com.

### Свой сервер в Казахстане (VPS)

По закону РК персональные данные граждан Казахстана нужно хранить на серверах в Казахстане — для настоящего запуска уточните требования у юриста и выберите хостинг в Казахстане.

1. Установите на сервер Docker.
2. Направьте домен на IP сервера.
3. Скопируйте проект на сервер и создайте рядом с `docker-compose.yml` файл `.env`:
   ```
   DOMAIN=nummaza.kz
   POSTGRES_PASSWORD=длинный-случайный-пароль
   ```
4. Запустите сервер, базу и Caddy (HTTPS-сертификат он получит сам):
   ```bash
   docker compose up -d --build
   ```

## APK для Android

```bash
android/build.sh
```

Сборка с сервером (адрес обязательно https://):

```bash
NUMMAZA_API_URL=https://nummaza.onrender.com android/build.sh
```

Нужны JDK 17+, python3, curl и zip. Скрипт сам скачивает с Maven Central aapt2 (из apktool-lib), dx и apksig, компилирует WebView-оболочку и подписывает APK схемой v2. Результат — `dist/NUMMAZA.apk` (Android 8.0+, targetSdk 34).

При первой сборке создаётся ключ `android/nummaza-release.p12` с паролем по умолчанию. Для публикации в Google Play создайте свой ключ и передайте его через переменные `KEYSTORE` и `KEYSTORE_PASS`; храните ключ в секрете и не добавляйте в git.

### Сборка на GitHub (без Linux и WSL)

`.github/workflows/android.yml` после каждого push проверяет обновления по воздуху (`android/test/run.sh`), собирает APK и кладёт его во вкладку **Actions** и в релиз `vX.Y`. Самый новый APK всегда по ссылке `https://github.com/<владелец>/NUMMAZA/releases/latest/download/NUMMAZA.apk`. Чтобы все сборки были подписаны одним ключом (иначе новый APK не встанет поверх старого), добавьте секреты `ANDROID_KEYSTORE_B64` (файл ключа в base64) и `ANDROID_KEYSTORE_PASS`.

## Обновления

- **Сайт**: код отдаётся с `Cache-Control: no-cache`, поэтому после деплоя достаточно обновить страницу. Открытая вкладка раз в 10 минут сверяет версию с сервером (`GET /api/bundle`) и показывает «Доступна новая версия → Обновить».
- **Android, веб-часть — по воздуху, без переустановки.** Приложение при запуске и при возврате в него (не чаще раза в 30 минут) спрашивает `GET /api/bundle`, скачивает только изменившиеся файлы, проверяет sha256 и предлагает «Обновить» (или применяет при следующем запуске). Страница по-прежнему открывается с `file:///android_asset/www/`, поэтому данные на телефоне не теряются. Если новая версия дважды подряд не запустилась, приложение само возвращается к встроенной. Так приходят все изменения в `app/`: экраны, разбор выписок, тексты.
- **Android, нативная часть** (Java, разрешения) — только новым APK. Сервер сообщает о нём (`APK_URL` и `VERSION_CODE` из `android/build.sh`), и на «Обзоре» появляется «Вышло приложение X.Y → Скачать». Если новый веб-код требует новой нативной части, поднимите `WebUpdater.NATIVE` и задайте на сервере `MIN_NATIVE` — старые APK не получат несовместимый код.

## iPhone

Отдельного приложения для iOS нет: сайт и есть приложение. В Safari: «Поделиться» → «На экран Домой» → «Добавить». Появляется иконка, NUMMAZA открывается на весь экран и работает без интернета (`app/sw.js`, `app/manifest.webmanifest`, иконки в `app/icons/` рисует `scripts/make_icons.py`). Обновления приходят так же, как на сайт, сразу после деплоя. Траты из уведомлений банка на iPhone невозможны: iOS не даёт приложениям читать уведомления.

Переменные сервера для обновлений: `APK_URL` (ссылка на последний APK), `MIN_NATIVE` (по умолчанию 0).
